# 科目Bの解説動画づくり（/fe-b-lesson-video）

1本目の **二分探索**（2026-10-29 完成）が見本。ソースは `~/lemo-opuscar/films/fe-binsearch-long/`、完成品は `notes/科目B解説動画/二分探索/`。
2本目からは、この見本のフォルダをコピーして、**台本（lines.json）と絵（film.js）と宣伝の区切り（promo.js）を書きかえる**。
回答は日本語で、運営者は初心者なので、画面のボタン名まで具体的に書く。

## 決まっていること（運営者が 2026-10-28・29 に決めた）
- **見る人**: 科目Bで、擬似言語を読むところからつまずいている人。言葉はやさしく、記号は読み方から説明する
- **本編**: 横長 1920×1080・30fps・約10分。大きな1枚のホワイトボードを章ごとの区画に分け、カメラが区画から区画へ動く（場面は切り替えない）。最後に引いてボード全体を見せる
- **ペンは画面に出さない**（`?nopens=1`。たくさん動いて見づらいため）。字と線は書き順に現れる。**消しゴムは出してよい**。後ろの字と重なるところを消すときは、跡を残さない（`wipe(..., 強さ 1)`）
- **色は3色**: 黒 = 書いたもの・枠、青 = low・high・番号、オレンジ = いちばん大事なもの（mid・答え）
- **入れるもの**: 本番と同じ形の**穴埋め問題**（問題文・空欄 a・b のあるプログラム・解答群 ア〜カ。印刷した問題用紙を磁石で留め、その上にペンで ✕・○）→ 5秒のカウントダウン → 答え合わせ（選択肢を2段階でしぼる）、YouTube のチャプター、BGM（マリンバ風、コードで作る）、最後に FE用語ドリルの紹介
- **練習問題の答えを先に言わない**: ひっかけポイントは、問題のあとの答え合わせで説明する
- **宣伝**: 本編と同じボードを、カメラだけ縦向きにして撮り直す（1080×1920、約50秒）。**ナレーションと字幕あり**（「リールは音なし」の決まりの例外）。文字は上 300px より下・1480px より上・右のボタンの列（x 900 より右）をよける
- **上げ方**: YouTube は本編とショートを**非公開**で上げる（`python upload_youtube.py --lesson <名前>`）。公開は運営者が YouTube Studio で押す。Instagram のリールは運営者がアプリで投稿する

## 手順
1. **アルゴリズムと構成を決める**: 科目Bでよく出るもの（`data/b/algorithms.json` の一覧も参考に）。章立ては見本と同じ11章（つかみ → 比べる → 考え方 → 擬似言語の読み方 → コードを1行ずつ → トレース①② → 穴埋め問題 → 答え合わせ → 計算量 → まとめ）を基本に、アルゴリズムに合わせて変える
2. **台本を PDF にして確認してもらう**: `notes/src/<名前>の解説動画_台本.html` → `python notes/src/make_pdf.py <名前>の解説動画_台本`（見本: `二分探索の解説動画_台本`）。ナレーションの全文（行ごとの番号 a01…）・ボードに書くもの・ボードの配置図・使うコード・トレース表・穴埋め問題と解答群・宣伝の構成を書く。**トレース表と穴埋めの正解・不正解の理由は、手で計算して確かめる**（不正解の選択肢は、どれも「なぜ違うか」を説明できるものだけ）。運営者の OK が出るまで先へ進まない
3. **作業フォルダを作る**: `~/lemo-opuscar/films/fe-<英数字>-long/` に、見本の `engine/`（縦長・横長の両方と、紙を貼る `under` に対応させた wb.js）・`fonts/`・`index.html`・`main.js`・`mix.py`・`tools/`・`promo/`・`build.sh` をコピーする。`film.js`・`promo.js`・`lines.json` は書き直す
4. **声**: `lines.json`（`text` は字幕に出す字、`say` は読ませ方）。英字は読み方をカタカナで `say` に書く（low → ロー、mid → ミッド、data[3] → データ かっこ 3、≦ → 以下、÷ → わる、-1 → マイナス1、科目B → 科目ビー）。`cd ~/lemo-opuscar` で `PYTHONIOENCODING=utf-8 .venv/Scripts/python core/tts/tts_zh.py films/<作業>/lines.json films/<作業>/voices --voice ja-JP-NanamiNeural --rate +5%`（edge-tts。ネットが要る。読み上げの文章は Microsoft に送られる）
5. **聞き取りチェック**: faster-whisper で行ごとに文字起こしして台本と並べ、読み間違いがないか見る（`.venv-asr` の Python。PyAV を通さず wav を numpy で読んで渡す。同じ音の別の字は気にしなくてよい）
6. **絵（film.js）**: 見本の作りに合わせる
   - ナレーションの開始時刻は `voices/dur.json` から順に決める（章の頭はカメラが動くので +1.8 秒、間を足す行は `EXTRA`）。絵はすべて `at(行, 割合)` で行の時刻にぶら下げる
   - 字は `mtext`（英数字は1本線の手書き EMS Tech、日本語は Klee One をなぞったところから出す）。描く指示はためて、最後に時刻順に実行する（ペンは1本ずつしか書けないため）
   - 磁石（low・high・今の行を指す矢印）、消しゴム、問題用紙（`board.under` に描く印刷物）、左上の章の見出し、カウントダウン、字幕（句読点・小さい字が行頭に来ないように）
   - 区画は、字幕の帯（下 約130px）と左上の章の見出しに字がかからない範囲に収める
7. **静止画で確かめる**: 各章の終わりのコマを `node core/render/still.mjs <作業> 秒 … --q nopens=1` で書き出し、ffmpeg で並べて見る。重なり・はみ出し・消し残し・ペンの遅れ（`[page] pen … late` の警告）を直す
8. **書き出し**: `sh films/<作業>/build.sh`（events → mix（声・BGM・効果音）→ 字幕とチャプター → 本編 → サムネイル → 宣伝）。本編は6分ほど、宣伝は1分ほど。音量は -14 LUFS になっているか確かめる
9. **YouTube の文字**: `YouTubeのタイトル.txt`・`YouTubeの説明文.txt`（チャプターは `out/chapters.json` から。サイトのリンク、「ナレーションは合成音声」「AI の支援で作成」を入れる）。「公式」「必ず合格」などは使わない
10. **完成フォルダに集める**: `notes/科目B解説動画/<名前>/` に `<名前>_本編_YouTube.mp4`・`<名前>_宣伝_リール・ショート.mp4`・`<名前>_サムネイル.jpg`・`<名前>_字幕.srt`・タイトルと説明文。完成した動画からもコマを抜き出して確かめる
11. **運営者に見てもらってから上げる**: `python upload_youtube.py --lesson <名前>`（本編・サムネイル・ショート。ショートの説明文には本編の URL が自動で入る。記録は `youtube.json`・`youtube_short.json`）。字幕は焼き込み済み。SRT を YouTube の字幕として足したいときは、運営者が YouTube Studio の「字幕」から上げる

## つまずきやすいところ
- このパソコンは ARM 版の Windows。Lemo-Opuscar の書き出しはそのまま動く（Manim・Remotion を使うときの回避策はメモ `manim-remotion-arm64` を参照）
- 宣伝のカメラは、ボードの上の端より上（壁）が見えないよう、上の見出しの帯（0〜600px）で隠れる位置にする
- 長い配列の移動平均は `np.convolve` だと遅すぎる（9分の音で10分以上）。累積和で計算する
- `rm` で作業フォルダの中身を消そうとすると安全チェックに止められる。静止画は別のフォルダ名に書き出せばよい
