# 用語の確認

月に1回、サイトを1つ選び、**古くなりやすい用語**（数字・年・法律・制度・版・料金などを含む説明）から40語ほどを、出典を調べて確かめる。1年で全サイトの用語がひととおり確かめられる。

## 手順

### 1. 試験の変更を見る

```powershell
curl -s https://raw.githubusercontent.com/yuki-fe/yogo-drill/watch-results/watch.md
```

- 試験の主催者などのページの、直近30日の変更（毎朝 yogo-drill の GitHub の自動実行が見張っている。見るページは `../yogo-drill/check/watch.json`）
- 変更があれば、まずそのページ（と、リンクされた PDF）を WebFetch で読み、**試験の範囲が変わったか**を確かめる。変わっていれば「4. 試験の範囲が変わったとき」へ
- 変更のあったサイトを、2 の `--site` で先にする

### 2. 確かめる用語を選ぶ

```powershell
$env:PYTHONIOENCODING="utf-8"; python review_tools/term_review.py            # 確かめた割合がいちばん少ないサイト
python review_tools/term_review.py --site ip -n 40                            # サイトと数を決めて
python review_tools/term_review.py --status                                   # サイトごとの確かめた数
```

一覧は `notes/用語の確認/<日付>_<サイト>.md`（公開しない）。各サイトのリポジトリはデスクトップの `02_個人開発/` の下（FE はこのリポジトリ、ほかは `ip-drill` など）。

### 3. 1語ずつ確かめる

- 説明（`desc`）の **目印の部分**（年・数字・法律の名前と中身・制度・版・料金・サービス名）を、WebSearch・WebFetch で調べる。出典は試験の主催者・官公庁・規格の団体・サービスの提供元のページを優先する。**覚えている知識だけで OK にしない**
- 一覧の「結果」の欄に書く:
  - `OK`
  - `直す: 新しい説明（出典の URL）` … 間違い・古い（法律の改正、サービス名の変更、数字の更新など）
  - `要確認: 理由` … 出典が見つからない・説が分かれる
- 説明は今の文体（短い2文ほど。「〜こと。」「〜方法。」）に合わせる。言い切れないことは書かない
- サイトの決まり: 「公式」「必ず合格」などは使わない。クラウドのサイト名に AWS、ディープラーニングに G検定、簿記に 日商 を入れない。医療事務は診療報酬の点数を書かない

### 4. 試験の範囲が変わったとき

- 新しいシラバス・出題区分表と、サイトの `data/terms.json` を比べ、**足す用語**（新しく範囲に入った）と、**範囲から外れた用語**を一覧にする（`notes/用語の確認/<日付>_<サイト>_範囲.md`）
- 用語の `id` は URL（`terms/0001.html`）なので、**変えない・使い回さない**。外れた用語を消すと、そのページが開けなくなる。消すかどうかは運営者に聞く（残して説明に「〇〇年度の試験から範囲外」と足す案も出す）
- 用語を足すときは、`data/yomi.json`（読み）・`data/imi.json`（意味の要点）も足す（ないと build.py が注意を出す）

### 5. 運営者に見せる

- 「直す」「要確認」の用語だけを、**今の説明 → 新しい説明（出典）** の形で短く見せ、直してよいか聞く。運営者は初心者寄りなので、専門的なことばは言いかえる
- OK が出たら、そのサイトの `data/terms.json` の `desc` を直す（意味の要点が変わるなら `data/imi.json` も）→ そのサイトのフォルダで `python build.py`（`.venv` があれば `.venv\Scripts\python build.py`。エラー・注意が出たら直す）
- 公開は運営者が **GitHub Desktop** で行う: 左上の「Current repository」でそのサイト（例: ip-drill）を選ぶ → 左下の「Summary」に「用語の確認」などと書く →「Commit to main」→ 上の「Push origin」

### 6. 記録する

```powershell
python review_tools/term_review.py --done "notes/用語の確認/<日付>_<サイト>.md"
```

一覧の用語を「確かめた」と記録する（1年たつと、また確かめる対象に入る）。直さなかった「要確認」も記録してよい。
