# 機能の提案

3つの係のエージェントが同時にサイトを見て案を出し、まとめ役（このスキルを動かす Claude）が1つの一覧にする。**案を選ぶのは運営者**。選ばれるまで実装しない。

引数でサイトを選べる（例: `/feature-scout ip-drill`）。なければ FE（このリポジトリ）。ほかのサイトはデスクトップの `02_個人開発/` の下のフォルダ。

## 手順

### 1. 材料を集める

```powershell
$env:PYTHONIOENCODING="utf-8"; python build.py                       # 注意・エラーも控える
..\yogo-drill\.venv\Scripts\python review_tools/site_shots.py           # 画面とページのエラー（ほかのサイトは --site ip-drill）
git log --oneline -15
```

- 前回までの記録 `notes/機能の提案/記録.md`（なければ作る）を読み、**採用・見送り・作った案**を控える
- アクセスの数字があると集客の係の質が上がる。運営者に LINE の「グラフ」「人気」の結果を聞いてもよい（なくても進める）

### 2. 3つの係に同時に頼む

Agent ツールを **1つの返事で3つ同時に** 呼ぶ（`subagent_type`: `learner-scout`・`growth-scout`・`code-scout`）。それぞれのプロンプトに入れるもの:

- 見るサイトのフォルダと、画面のフォルダ（`notes/機能の提案/画面/<日付>/<サイト>/`）
- build.py の注意・エラー、最近の commit
- 記録.md の「見送った案」「作った案」（同じ案を出させない）
- アクセスの数字（あれば）

### 3. まとめる

- 同じ・似ている案は1つにまとめ、どの係が出したかを書く（2つ以上の係が出した案は信頼が高い）
- **決まりごと（CLAUDE.md）に合わない案は外す**: 主催者と関係があるように見える言葉、確かめられない言い切り、Instagram・YouTube への自動投稿、PR の表示を消す、用語の id を変える、有料のサーバーが要る など。外したものは一覧の最後に理由つきで短く書く
- 係が「根拠」に書いたファイル・画面は、まとめ役も実際に開いて確かめる（思いこみの案を残さない）
- 順番: 効果が大きく手間が小さいものから。すぐ直せる小さな不具合は別の欄

一覧を `notes/機能の提案/<日付>_<サイト>.md` に書き、運営者には上位5件ほどを短く見せて、**どれを作るか聞く**（AskUserQuestion、複数選べる形）。

### 4. 選ばれた案を作る

- EnterWorktree で作業用のコピーを作り、そこで実装する（本体を汚さない）
- `python build.py` が注意なく通ること。科目Bを触ったら `checks/b-check.html` が ALL OK、ボットを触ったら `python line-bot/test/run_test.py` が ALL OK
- 見た目を変えたら `site_shots.py` で撮り直し、画像で確かめる
- 全サイト共通のファイル（`layout.css`・`typing.js` など）を直したら、ほかのサイトにもコピーする（運営者に確かめてから）
- 終わったら変えたファイルと確かめた結果を報告する。取り込み（commit・push）は運営者が **GitHub Desktop** でする。手順はボタン名まで書く

### 5. 記録する

`notes/機能の提案/記録.md` に追記する:

```
## <日付> <サイト>
- 作った: <案の名前>
- 見送った: <案の名前>（理由）
- 次に回す: <案の名前>
```
